# 后台托管功能设计

## 目标

为 Windows Qt Quick 原生客户端增加后台托管能力：窗口最小化或关闭到系统托盘后，继续接收直播状态通知并保留音频播放；后台不渲染视频画面和弹幕，恢复窗口后重新显示视频与弹幕。

## 已确认的产品行为

- 最小化窗口：进入后台托管，不退出进程。
- 点击窗口关闭：隐藏到系统托盘，不退出进程。
- 托盘菜单包含“显示窗口”和“退出程序”。
- 托盘“退出程序”执行真正退出：停止视频/音频播放、弹幕会话、收藏监控和 StreamGet 子进程。
- 后台继续播放音频：单声道只保留当前声音焦点，多声道保留各房间当前音量，全局静音继续生效。
- 后台停止视频和弹幕渲染，但不销毁房间状态；回到前台后恢复渲染和弹幕显示。
- 播放错误、恢复、开播/下播及收藏标题变化通知继续按现有通知策略工作。
- 不引入 Qt Widgets、Qt WebEngine、Chromium 或 Electron。

## 方案与取舍

### 方案 A：`QSystemTrayIcon`

实现成本较低，但会重新引入 Qt Widgets 运行时和部署依赖，与当前纯 Qt Quick 架构冲突，放弃。

### 方案 B：QML 仅控制窗口隐藏，托盘由脚本或外部进程实现

可以避免 C++ 平台代码，但托盘生命周期、真正退出和窗口消息转发不可靠，安装包中还会增加额外进程，放弃。

### 方案 C：Windows 原生托盘服务（推荐）

使用 `Shell_NotifyIcon`、隐藏消息窗口和 `WM_APP` 自定义消息，在 C++ 中封装托盘生命周期；`AppController` 暴露托管状态和显示/退出命令，QML 只处理窗口状态与用户界面。该方案不增加 Widgets/WebEngine 依赖，能精确区分隐藏、恢复和真正退出。

## 架构

### `WindowsTrayService`

新增 `native/src/app/windows_tray_service.h/.cpp`，仅在 Windows 编译实现托盘服务，非 Windows 提供空实现以保持跨平台构建。

职责：

1. 创建消息窗口并注册托盘图标。
2. 创建托盘菜单：显示窗口、退出程序。
3. 处理左键/双击显示窗口、菜单命令和销毁消息。
4. 发出 `showRequested()`、`quitRequested()` 信号。
5. 在析构时移除托盘图标并销毁消息窗口。

托盘图标复用当前程序图标资源；若资源加载失败，使用系统默认应用图标并记录诊断信息，不阻止主程序启动。

### `AppController` 生命周期接口

新增或调整以下接口：

- `Q_PROPERTY(bool backgroundHosted READ backgroundHosted NOTIFY backgroundHostedChanged)`
- `Q_INVOKABLE void minimizeToBackground()`：标记后台托管并隐藏/最小化窗口。
- `Q_INVOKABLE void closeToTray()`：标记后台托管并隐藏窗口。
- `Q_INVOKABLE void restoreFromBackground()`：显示窗口、恢复渲染和弹幕。
- `Q_INVOKABLE void requestQuit()`：执行一次性 shutdown 后关闭应用。

保留 `shutdown()` 作为析构和真正退出的幂等内部路径；窗口关闭事件不得直接调用 `shutdown()`。

后台状态由 `AppController` 统一维护，避免 QML visibility、Windows 消息和播放器生命周期出现竞争。重复最小化、重复恢复和重复退出都必须幂等。

### 播放与弹幕生命周期

`MultiRoomCoordinator` 保持房间会话、音频轨道和音量状态不变。进入后台时逐个通知 `MpvQuickItem`：

- 保留 libmpv 播放会话和音频输出。
- 暂停或解绑 Qt Quick 视频渲染目标，不调用会停止音频的 `stop()`。
- 弹幕控制器停止向可视层推送绘制数据，但保留连接/状态；若当前实现无法安全暂停绘制，则暂停弹幕视图并保留会话，恢复时触发一次同步。

恢复前台时重新绑定可见的 `MpvQuickItem`，触发一次渲染刷新，并重新同步所有活动房间的弹幕显示状态。恢复失败只影响对应房间的画面/弹幕，不得导致进程退出或影响后台音频。

### QML 窗口行为

`Main.qml` 的 `onClosing` 改为调用 `appController.closeToTray()` 并将 `close.accepted` 设为 `false`，避免 Qt 直接销毁窗口。窗口最小化事件通过 `visibility` 变化或 C++ 窗口事件桥接到 `minimizeToBackground()`；从托盘恢复时调用 `restoreFromBackground()`。

窗口恢复后保留原最大化/全屏状态。全屏退出、系统关机和应用显式退出走 `requestQuit()`，不隐藏到托盘。

## 数据流

1. 用户最小化或关闭窗口。
2. `AppController` 将状态置为后台托管，调用渲染暂停接口并隐藏窗口。
3. `WindowsTrayService` 保持图标和菜单，`FavoriteMonitor`、通知服务、StreamGet 与音频播放继续运行。
4. 用户点击托盘“显示窗口”或图标。
5. `AppController` 显示窗口、恢复视频渲染、恢复弹幕视图并刷新状态。
6. 用户点击“退出程序”或系统结束进程。
7. `requestQuit()` 设置退出标志，按现有顺序停止弹幕、协调器、收藏监控、StreamGet 和通知服务，移除托盘图标后退出 Qt 事件循环。

## 错误处理

- 托盘创建失败：记录错误并保持窗口可用；关闭按钮退化为真正退出并显示一次提示。
- 恢复渲染失败：显示现有播放错误状态，后台音频不受影响。
- 重复收到关闭/退出消息：通过幂等标志防止二次释放。
- StreamGet、弹幕或通知服务异常：沿用现有重试与通知策略，不因后台模式改变错误语义。
- 应用退出前始终移除托盘图标，避免系统托盘残留幽灵图标。

## 测试设计

### 单元测试

- 后台状态进入、恢复和退出的幂等性。
- `closeToTray()` 不调用 `shutdown()`；`requestQuit()` 调用一次 shutdown。
- 托盘服务菜单命令分别发出显示和退出信号。
- 后台切换不改变房间列表、主房间、音频焦点、音量和全局静音状态。

### 集成测试

- 启动 1/4/6/9 路后最小化，确认 StreamGet、音频和状态监控仍运行。
- 关闭到托盘后由托盘恢复，确认视频首帧、弹幕和窗口状态恢复。
- 托盘退出后确认进程结束、StreamGet 子进程结束、无残留托盘图标。
- 播放失败、开播通知和收藏标题变化在后台仍能触发 Windows 通知。

### Windows 手工验收

- Windows 10/11，窗口化、最大化、全屏三种状态分别执行最小化、关闭到托盘和恢复。
- 重复点击最小化、关闭、恢复和退出，确认无崩溃、黑屏或双重通知。
- 关闭程序后重新启动，确认房间、布局、音频和通知偏好正确恢复。

## 非目标

- 不新增后台录制、转码、系统服务或开机自启。
- 不改变现有布局算法、播放源解析、收藏排序和通知偏好语义。
- 不在后台渲染隐藏的视频帧或弹幕画面。
