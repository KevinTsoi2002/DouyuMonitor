# CSTG 特勤终端信息架构

更新：2026-10-30，Asia/Shanghai。状态：用户已确认当前 R3 方案，进入正式设计；本文件规定设计与后续原生适配，不代表 Figma、QML 或原生回归已经完成。

## 1. 决策基线

采用 C 组件结构，C1 为夜间模式，C3 为白天模式。应用保留原生 Windows x64、Qt Quick/QML、C++、libmpv 和独立 StreamGet 服务。网页只作为视觉与交互参考。

已确认的应用壳：

- 80px 窄侧栏；CSTG 字标 16px，导航品牌图标 40px，线性图标 26px。
- 36px 标题栏；保留应用图标，软件名称使用用户提供的图片字标。C1 使用浅色图，C3 使用深色图；桌面等比容器 210×24px。网页的 160×22px 紧凑容器仅供窄屏降级参考。
- 观看页以视频为主体；不设置常驻页面标题、中央说明卡或画面内工具按钮。观看工具入口放在现有标题栏，按需打开覆盖抽屉。
- 沉浸时收起应用壳，通过顶部右侧边缘的悬停／键盘聚焦入口或 T 唤出工具；Esc 优先关闭当前浮层，再退出沉浸。
- 颜色切换不改变当前页面、选中对象、房间、布局、音频、弹幕或播放器身份。

本文件取代此前“三套候选、尚未批准”的信息架构表述。R1/R2 文件作为历史记录保留。数据和现有行为依据 [UI_AUDIT.md](UI_AUDIT.md)、[DATA_CONSTRAINTS.md](DATA_CONSTRAINTS.md)，正式画面要求见 [SCREEN_SPECIFICATIONS.md](SCREEN_SPECIFICATIONS.md)。

## 3. 页面、状态所有者与现有边界

以下“目标路由”是设计标识，不是已存在的 C++ API。

| 目标路由 | 现有实现 | 数据所有者 | 适配要求 |
| --- | --- | --- | --- |
| directory 主播导航 | GuildNavigationPanel、GuildMemberRow、GuildRankHoverCard；当前挂在 monitoring 左面板 | AppController.guildRoster、workspace.teams、线上榜单投影 | 提升为页面；保留队伍层级、增量刷新和解析状态。页面可见性与 setNavigationVisible() 同步，该命令控制 resolver 启停，不只是宽度开关。 |
| ranking 团播榜单 | MaoziRankPage、SeasonArchivePanel；当前路由 maoziRank | s1Archive 优先，按现有规则回退 maoziRank | 保留五标签、源顺序、赛程分页和参与者详情；采用 C 的名单／详情组织。 |
| watch 直播工作区 | WorkspaceGrid、RoomTile；当前路由 monitoring | rooms、workspace、danmaku、monitoring | 保持播放器绑定和会话；把辅助入口移到覆盖工具中。 |
| settings 设置 | SettingsPage | 关闭偏好、更新、活动映射及队伍接口 | 保留现有四组；新增外观组承接已确认的日夜切换。 |

页面搜索、当前标签、详情选择和抽屉开关属于展示状态。房间、声音、画质、队伍、弹幕、预设与保存结果来自控制器或公开模型。展示层可以筛选只读投影，但不能维护第二份权威业务状态。

原生 currentView 目前只有 monitoring/settings/maoziRank。增加主播导航页面属于后续 QML 适配；切换到导航不得清空工作区或把页面关闭当作房间移除。保留播放会话和现有渲染暂停规则，不能复制网页的 DOM 重建方式。

## 4. 主流程与动作契约

| 流程 | 必须可达的操作 | 守卫与反馈 |
| --- | --- | --- |
| 找成员 → 确认房间 → 加入 → 观看 | 选择成员、手动确认房间、加入、前往工作区 | status、liveState、active 分开；确认号只接受 1–20 位数字；未知或歧义匹配不得自动认领。容量取 workspace.maxRooms，加入成功后再改变界面状态。 |
| 搜索房间 → 选择候选 → 添加 | 房间号／链接／主播名、搜索结果、添加 | 保留 idle/searching/empty/error；失败保留输入；只有成功才关闭添加弹窗。 |
| 当前房间 → 历史／收藏 → 重新打开 | 收藏、排序、添加、删除未打开历史、当前房间定位 | 复用 libraryRooms 与现有过滤条件；不能把收藏或历史删除解释为退出房间。 |
| 多路观看 → 调声音／画质／弹幕 | 逐房和全局入口均存在；密集格子可从工具抽屉操作 | 声音焦点、多路静音、全局静音不同；画质只展示真实可用项，区分请求值和有效值。 |
| 改布局 → 主／次主画面 | 自动、主画面、双主画面；主次主选择 | 使用 auto/primary/primary-two，双主不足 4 房时禁用并解释；容量与资格由业务层判定。 |
| 查成绩 → 选参与者／场次 → 返回 | 五标签、搜索、日期、详情、分页、统计 | 档案与实时回退标注来源；不新增表头排序、投票或缺失成绩。返回恢复相应列表位置和查询上下文。 |
| 管队伍 → 野榜导入预览 → 确认 | 新增、改名、删队、排序、成员分配；导入预览与问题列表 | 来源变化使预览失效；canConfirm 为准；保存失败说明“本地队伍未更改”，保留可重试路径。 |
| 设置变更 → 保存结果 | 即时保存、显式保存、失败重试 | 关闭偏好、通知、活动映射、工作区和主题各自遵循保存边界；不能用统一“已保存”掩盖失败。 |
| 关闭 → 后台或退出 → 恢复 | 取消、后台、完全退出、记住选择、托盘恢复 | 通过原有生命周期命令；保留服务停止、渲染暂停、恢复和回调释放。 |

## 5. 观看工具与浮层层级

常态观看网格不为工具抽屉预留列宽。工具打开时覆盖当前画面；关闭后恢复完整观看区域，不能触发重排、重新解析播放源或重建播放器。覆盖属于用户主动打开的临时状态，不能恢复成常驻面板。

层级顺序为：视频 → 弹幕 → 悬停／焦点逐房控件 → 工具抽屉与菜单 → 模态对话框 → 必要错误反馈。抽屉打开后保留关闭入口、选中房间和清楚的声音状态。密集画面即使隐藏内嵌控制，也能从房间列表访问音量、画质、弹幕、重试、主次主和移除。

| 表面 | 目标入口与关系 | 现有内容边界 |
| --- | --- | --- |
| 观看工具抽屉 | 标题栏、T、沉浸边缘；容纳功能分区 | 新展示容器，调用已有命令。不能把布局、音频、弹幕简化成网页演示的几个开关。 |
| 房间工具 | 观看工具房间分区、Ctrl+Shift+S | RoomSidebar 与 RoomLibraryView 的当前／历史／收藏。既有 sidebarVisible 和预设恢复只适配为房间工具展示，不与沉浸状态混用。 |
| 添加房间对话框 | 房间工具、Ctrl+Shift+A、空工作区 | AddRoomDialog。 |
| 音频／布局面板 | 观看工具及保留快捷入口 | 原 AppHeader 音频浮层和布局 Menu；使用一致的关闭／回焦点语义。 |
| 弹幕设置 | 观看工具、Ctrl+Shift+D | DanmakuSettingsPanel 三页、全局和逐房开关。 |
| 监控面板 | 观看工具、Ctrl+Shift+M | MonitoringStatusPanel；通知设置作为子流程。 |
| 通知设置对话框 | 监控面板 | NotificationSettingsDialog 六项。 |
| 工作区预设 | 观看工具、Ctrl+Shift+W | WorkspacePresetsPanel；保留延后应用的时序。 |
| 队伍管理对话框 | 主播导航及设置 | TeamManagerDialog；导入预览仍在其上下文内。 |
| 关闭行为对话框 | 窗口关闭且偏好 ask | CloseBehaviorDialog；初始焦点为取消。 |
| 成员榜单悬浮信息 | 公会成员悬停，键盘选择后可读同等内容 | GuildRankHoverCard；延迟、失焦清理、边界定位。 |
| 逐房更多与画质菜单 | 房间控制层及房间工具中的同等操作 | RoomTile 真实资格与防双击误触。 |
| Toast 与工作区未保存提示 | 控制器反馈 | 保留消息等级、超时、手动关闭与独立保存重试。 |

打开子对话框时保留其来源，关闭后回到触发按钮；触发对象消失时回到当前页面的稳定入口。Esc 只处理最上层可关闭表面，一次按键不得同时关闭对话框和退出沉浸。输入法组合、编辑文本、下拉框展开期间，按键先交给控件。

## 6. 数据来源与界面真实性

| 内容 | 可用字段与来源 | 展示约束 |
| --- | --- | --- |
| 公会成员 | guildRoster 的身份、解析、在线、加入状态与匹配后的线上信息 | 固定身份、缓存映射和线上榜单分别标明；未知不显示离线。 |
| S1 赛季档案 | s1Archive 的排行、定级、常规赛、决赛、足球及元数据 | 使用 season/capturedAt；不生成“实时人数”或“当前离线”。缺失显示“—”或“未记录”。 |
| 线上榜单回退 | maoziRank 的数据、loading、更新时间、同步错误 | 区分首次加载、刷新中、空、旧数据过期和不可用；旧结果不能标成新结果。 |
| 工作区房间 | RoomListModel | viewerLabel 只当展示字符串，不相加生成总观众；音频、播放与直播状态分开。 |
| 监控 | online/offline/error、通知状态、现有恢复状态 | 错误数可能和在线数重叠；不相加为总数；不增加无来源的 CPU/GPU/内存、趋势或运行时长。 |
| 弹幕 | DanmakuController 和房间角色 | 展示当前房间的治理统计；不解释为全站统计或稳定性证明。 |

当前源码容量为 Phase16 默认 16 路、Phase24 构建可选 24 路；弹幕和多音轨有独立预算。该事实与旧仓库说明的 9/10 路有冲突，产品始终读取当前模型，不把某个构建值写死在标题、按钮或验证上限。

网页“示例10001”、北屿等合成姓名、15.60 等示例分数、四路构图、状态演示选择器和本地意见记录都不构成生产字段、默认值或业务接口。

## 8. 持久化与安全边界

工作区保留 DouyuMonitor/nativeWorkspaceV1 的现有 schema、字段和迁移；活动角色使用独立 DouyuMonitor/eventMappingV1。应用标识、QML 模块、安装标识及可执行文件名保持现状。主题和展示状态如需新增保存字段，必须在实施计划中说明默认值、旧版本读取和写入失败，不由本设计文档擅自更换存储位置。

不保存或显示真实播放地址、查询参数、Cookie、Token、签名、原始服务诊断或弹幕认证帧。错误界面用已有业务错误码和可恢复动作。页面切换、模式切换和覆盖层打开不得绕过 AppController → MultiRoomCoordinator → RoomSession。
