# 新增房间后的自动推荐布局设计

## 目标

让工作区在“自动推荐”模式下随房间数量变化使用合适的网格布局，同时保留用户手动选择布局后的控制权。

## 状态模型

继续使用工作区已有的 `layoutId` 字段表示布局模式：

- `auto`：自动推荐模式。布局引擎根据当前房间数量解析出实际布局。
- 具体布局 ID（如 `single`、`grid-2x2`、`grid-3x2`、`grid-3x3`、`primary-two`、`split-horizontal`、`split-vertical`）：手动锁定模式。

不新增第二个“锁定”布尔字段，避免状态出现两个来源。调用 `setLayout` 选择具体布局即完成锁定，选择 `auto` 即恢复自动推荐。

## 推荐规则

| 房间数量 | 推荐布局 |
| --- | --- |
| 0 | 空工作区，不生成布局槽位 |
| 1 | `single` |
| 2–4 | `grid-2x2` |
| 5–6 | `grid-3x2` |
| 7–9 | `grid-3x3` |

房间数量受现有九个房间上限约束。自动布局返回稳定的行列槽位，房间顺序仍由工作区排序决定。

## 交互行为

1. 新工作区默认处于 `auto` 模式。
2. 在 `auto` 模式中新增房间时，`layoutId` 保持为 `auto`，布局引擎按新增后的数量立即使用新的推荐布局。
3. 手动选择布局后，新增或删除房间不会覆盖该布局；布局引擎对超出该布局容量的房间继续使用已有自适应兜底。
4. 用户再次选择“自动推荐”后，立即按照当前房间数量恢复推荐布局。
5. 删除房间不会强制把手动布局切换为自动；自动模式下删除后的画面由当前数量重新推荐。

## UI 表现

布局菜单新增“自动推荐”选项，选中条件为 `layoutId === 'auto'`。菜单触发器或菜单辅助文本展示当前模式；自动模式下可显示当前实际推荐布局名称，但不能将其误认为手动锁定。

布局选项的既有具体布局保持不变。自动布局的提示明确说明“新增房间时自动适配”。

## 持久化与兼容

- 工作区快照继续保存 `layoutId`，允许值集合增加 `auto`。
- 旧快照缺少该值时按现有具体布局解析，避免破坏用户已经保存的手动选择。
- 新建且无持久化快照的工作区默认写入 `auto`；第一次其他设置触发持久化时也保存 `auto`。
- 快照不保存计算后的实际布局，只保存模式，启动后根据房间数量重新计算。

## 错误处理与边界

- 自动模式仅依赖房间数量，不依赖播放源、弹幕或网络状态。
- 房间数量为 0 时返回空槽位；数量达到 9 时仍使用 `grid-3x3`。
- 未知布局 ID 继续沿用布局引擎的自适应兜底，不影响自动模式。

## 测试策略

- 领域层：验证自动推荐在 0、1、2、4、5、6、7、9 个房间的布局 ID/槽位结果。
- 工作区 store：验证默认 `auto`、自动新增保持 `auto`、手动布局在新增后不被覆盖、重新选择 `auto` 后恢复推荐。
- 持久化：验证 `auto` 快照可往返读取，旧具体布局快照仍可恢复，非法布局值仍回退到 `single`。
- UI：验证菜单出现“自动推荐”、选中状态和选择行为；现有具体布局选项继续可用。
- 回归：运行完整 Vitest、TypeScript 类型检查、生产构建，并用 Playwright 在 Electron 窗口中顺序新增房间确认布局视觉和交互结果。

## 非目标

- 不改变播放流获取、合规直连校验、弹幕连接或房间排序算法。
- 不在本次功能中新增用户自定义网格、拖拽调整网格尺寸或跨设备同步。
