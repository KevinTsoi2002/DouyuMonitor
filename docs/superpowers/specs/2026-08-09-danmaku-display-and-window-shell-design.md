# 高密度弹幕与窗口外壳设计

## 目标

本次改动完成三项用户界面能力：

1. 将每个直播间当前最多显示 5 条的纵向消息条，替换为高密度、持续从右向左移动的多轨弹幕。
2. 提供一套作用于所有直播间的全局弹幕设置，并保存用户选择。
3. 让桌面侧栏可以完全收起，同时将 Electron 系统标题栏替换为应用内窗口控制。

## 已确认的产品决策

- 弹幕设置对所有直播间统一生效，不提供单房间覆盖。
- 用户通过顶部全局弹幕按钮旁的齿轮按钮打开设置面板。
- 高峰期优先保持实时；等待队列超过保护阈值时丢弃最旧消息。
- 使用 DOM 多轨调度器。调度器按消息宽度、画面尺寸和轨道占用安排发射，避免同轨追尾。
- 弹幕从画面右侧外进入，完整移出左侧后回收。
- 弹幕使用白字黑描边，昵称使用强调色，不显示整条背景。
- 左侧房间列表收起后不占用画面宽度，仅由左上角按钮负责重新展开。
- Electron 隐藏系统标题栏和菜单栏，在应用顶栏提供最小化、最大化/还原和关闭按钮。

## 弹幕设置模型

新增全局 `DanmakuSettings`：

| 字段 | 类型和值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `durationSeconds` | 4-15 秒 | 8 | 完成一次横向移动的时长；滑块最左映射 15 秒，最右映射 4 秒 |
| `fontSize` | 14-36 px | 24 | 弹幕正文字号 |
| `opacity` | 0.3-1 | 0.9 | 昵称和正文的整体不透明度 |
| `region` | `full`、`top`、`bottom` | `full` | 全屏、上半区或下半区 |
| `density` | `massive`、`normal`、`reduced` | `normal` | 海量、正常或精简 |
| `fontFamily` | `simhei`、`microsoft-yahei` | `microsoft-yahei` | 黑体或微软雅黑 |
| `rendering` | `native`、`advanced` | `native` | 标准描边或增强描边与阴影 |

速度、大小和不透明度各有独立重置按钮。选项设置不提供单项重置，用户可以直接选择默认项。所有更改即时写入内存并触发工作区持久化，不需要保存按钮。

`native` 使用白字、1 px 黑色描边和轻量阴影。`advanced` 使用更粗的多层描边与阴影，提高复杂画面上的可读性。两种模式都保留昵称强调色，不增加消息背景。

## 设置面板

顶部全局弹幕按钮旁新增齿轮图标。点击后在按钮下方打开紧凑浮层：

- 上半部分依次显示速度、大小和不透明度滑块，每行带一个“重置”按钮。
- 下半部分依次显示弹幕区域、弹幕数量、弹幕字体和字体渲染。
- 当前选项使用应用现有橙色强调色。
- 点击面板外部或按 Escape 关闭面板。
- 面板打开时不会阻止直播播放或弹幕移动。

浏览器开发模式和 Electron 模式使用同一设置面板。

## 多轨调度器

### 职责

新建纯逻辑调度模块，负责：

- 根据容器宽高、区域、字号和密度生成可用轨道。
- 根据消息文本宽度和移动时长计算轨道占用。
- 选择不会与现有消息碰撞的轨道。
- 控制三种密度的最小发射间隔。
- 在没有安全轨道时保留消息，等待后续调度。
- 删除超出队列保护阈值的最旧消息，并累计丢弃计数。

React 弹幕组件负责读取尺寸、测量文字、渲染消息、监听动画结束并通知调度器回收。调度算法不依赖 DOM，单元测试可以直接输入尺寸和消息宽度。

### 轨道计算

- 轨道行高使用 `fontSize * 1.35`，至少生成一条轨道。
- `full` 使用整个视频可见高度。
- `top` 使用视频上半部分。
- `bottom` 使用视频下半部分，并从画面中线开始排列。
- `massive` 使用全部物理轨道。
- `normal` 使用约 70% 的物理轨道，至少一条。
- `reduced` 使用约 40% 的物理轨道，至少一条。

同一轨道可以同时存在多条弹幕，前提是前一条弹幕尾部已经离开右边界安全距离，并且后一条在前一条离开画面前不会追上。调度器使用消息宽度、容器宽度、发射时间和移动时长判断该条件。

### 发射节奏

| 数量档位 | 轨道占用 | 最小发射间隔 |
| --- | --- | --- |
| 海量 | 100% | 80 ms |
| 正常 | 约 70% | 180 ms |
| 精简 | 约 40% | 360 ms |

这些间隔限制每个直播间自己的调度频率，不限制同时在屏幕上的消息数量，也不会让一个房间阻塞另一个房间。实际并发数量由画面高度、字号、消息长度、速度和轨道占用共同决定。代码不再包含固定的 `MAX_VISIBLE_DANMAKU = 5`。

### 队列与回收

- 每个房间最多保留 300 条等待消息。
- 新批次导致队列超限时，从队首删除最旧消息并增加 `dropped`。
- 已发射消息不计入等待队列上限。
- 弹幕完整移出左边界后删除对应 DOM 节点并释放轨道记录。
- 用户关闭全局弹幕、关闭单房间弹幕或移除房间时，清空对应等待队列、活动消息和调度状态。
- 连接中断不伪造弹幕；已经发射的消息完成当前动画，等待队列继续按现有数据排空。

## 设置变更与尺寸变化

- 字体家族、描边和不透明度设置立即应用到屏幕中的消息。
- 速度、区域、字号和数量设置从下一条发射消息开始使用；已经发射的消息按原路径完成，避免位置跳变。
- 每个直播画面使用 `ResizeObserver` 监听尺寸。布局切换、侧栏收起或窗口缩放后，调度器按新尺寸重建后续轨道。
- 尺寸变化前已经发射的消息继续移动并在离开画面后回收。新消息只进入新计算的轨道。
- 容器宽高为 0 时暂停发射；容器恢复尺寸后继续处理最新队列。

## 状态与持久化

全局弹幕设置归工作区状态管理，与 `globalDanmakuEnabled` 一起由现有工作区 store 提供。侧栏展开状态也进入工作区快照。

工作区快照升级到 schema v2：

- v2 保存 `danmakuSettings` 和 `sidebarOpen`。
- 读取 v1 快照时保留房间、布局、音频和弹幕开关，并补入默认弹幕设置与默认侧栏状态。
- 字段缺失、类型错误或数值越界时只回退对应字段，不丢弃整个有效快照。
- 滑块数值在读取时限制到允许范围。

默认侧栏状态保持现有规则：桌面宽度大于 820 px 时展开，移动端关闭。保存过的 `sidebarOpen` 优先于默认规则。

## 侧栏收起

- 顶部侧栏切换按钮在桌面端和移动端都可见。
- 桌面端收起侧栏后，侧栏宽度和布局占位都变为 0，视频网格占用全部可用宽度。
- 不在画布左缘显示重复的展开按钮；左上角按钮是唯一的侧栏开关。
- 移动端沿用覆盖式侧栏；关闭时不遮挡工作区。
- 侧栏开关使用明确的 `aria-label` 和 `aria-expanded`。

## Electron 无边框窗口

主窗口使用 `frame: false` 并隐藏菜单栏。应用顶栏的空白区域使用 `-webkit-app-region: drag`，按钮、菜单、滑块和其他交互区域统一使用 `-webkit-app-region: no-drag`。

顶栏右侧增加三个窗口控制按钮：

- 最小化
- 最大化或还原，根据当前窗口状态切换图标和辅助文本
- 关闭

preload 只暴露以下带类型的窗口能力：

- `minimizeWindow()`
- `toggleMaximizeWindow()`
- `closeWindow()`
- `onMaximizedChanged(listener)`

主进程从 IPC 事件的 `sender` 查找发起操作的 `BrowserWindow`，不会让 renderer 指定目标窗口。IPC 不接受路径、命令或任意频道名。现有 `contextIsolation: true`、`nodeIntegration: false` 和 `sandbox: true` 保持不变。

普通浏览器模式没有窗口 API，应用不渲染 Electron 窗口控制按钮。其余界面和弹幕功能保持可用。

## 异常处理

- 文字测量失败时使用“字符数 × 字号”的保守宽度估算，消息仍可进入轨道。
- `ResizeObserver` 不可用时在首次渲染和窗口 `resize` 事件中测量容器。
- 动画结束事件缺失时，调度器按预计结束时间加宽限期清理消息，防止节点滞留。
- 本地存储不可用时继续使用当前会话设置，不向用户暴露内部异常。
- 窗口 IPC 找不到所属窗口时直接返回，不影响 renderer。

## 测试与验收

### 单元测试

- 根据区域、字号和密度计算轨道数量。
- 同轨消息满足安全距离且不会追尾；长消息和不同速度也不碰撞。
- 海量、正常和精简使用对应轨道比例与发射间隔。
- 300 条等待队列保护生效，并按先进先出丢弃旧消息。
- 消息动画结束、超时、关闭弹幕和移除房间都能清理状态。
- 默认设置、字段校验、单项重置和 v1 到 v2 迁移正确。
- preload 只调用已批准的窗口频道，主进程只操作事件来源窗口。

### 组件与集成测试

- 设置面板可打开、关闭、选择选项和调整滑块。
- 设置变化同步到全部直播间，重新加载后恢复。
- 屏幕并发弹幕不受固定 5 条限制，消息持续从右向左移动。
- 桌面侧栏完全释放宽度，并可由左上角按钮恢复；移动端保持覆盖式行为。
- 浏览器模式不显示窗口按钮，Electron 模式显示并更新最大化状态。

### 运行时验证

- 使用 Playwright 在单房间、2x2 和 3x3 布局中注入高频弹幕，检查轨道、裁剪、设置变化和布局切换。
- 在 9 个房间各注入 300 条突发消息，确认界面仍可操作、等待队列不超过保护阈值、活动节点最终回收且没有未处理异常。
- 在 Electron 窗口中验证拖动、最小化、最大化、还原和关闭。
- 检查桌面和移动视口，确认设置面板、侧栏按钮、窗口按钮和直播画面不重叠。
- 运行完整测试、类型检查、生产构建和 Windows 安装包构建。

## 非目标

- 不修改斗鱼播放流获取、弹幕协议、房间搜索或合规直连校验。
- 不增加单房间弹幕样式覆盖、关键词过滤、屏蔽用户、彩色正文或礼物动画。
- 不使用 Canvas、WebGL 或第三方弹幕渲染引擎。
- 不更改九个直播间的产品上限和自动推荐布局规则。
- 不处理代码签名。
