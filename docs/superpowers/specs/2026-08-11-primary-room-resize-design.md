# 主直播间画面比例拖动设计

## 状态

- 日期：2026-08-11
- 结论：采用约束式分隔线拖动，松手后吸附到推荐比例
- 适用布局：沿用现有 `primary-two` 布局 ID，界面名称使用“主画面布局”

## 目标

用户可以拖动主直播间与副画面区域之间的分隔线，调整主直播间占据的空间。系统在拖动期间连续预览尺寸，松手后吸附到可用比例，并在剩余区域重新排列其他直播间。

切换主直播间时，新主直播间与当前主直播间交换画面位置。其他直播间保持原位，直播播放器不重新挂载。

## 设计原则

1. 只有主直播间可以改变画面区域大小。
2. 视频保持原始宽高比，布局只调整画面容器，不拉伸视频内容。
3. 副画面使用剩余空间自动排列，不允许重叠、溢出或小于可用下限。
4. 拖动只改变一条分隔线，避免二维自由缩放带来的比例失真和不稳定重排。
5. 主直播间切换只交换两个槽位，不重排整个画面列表。

## 用户交互

### 进入主画面布局

用户从现有布局菜单选择“主画面布局”。该选项继续使用持久化值 `primary-two`，旧版本保存的布局无需迁移。

- 只有一个直播间时，系统隐藏分隔线，画面占满工作区。
- 两个及以上直播间时，系统显示主画面区域、分隔线和副画面区域。
- 其他均分布局不显示尺寸调整分隔线。

### 调整主画面大小

- 分隔线使用 8px 命中区域和 2px 可见线。
- 桌面宽度下使用左右分割，鼠标显示 `col-resize`。
- 窄窗口下使用上下分割，鼠标显示 `row-resize`。
- 拖动时用 CSS 变量连续更新预览，不写入全局状态。
- 松手后吸附到 `50%`、`60%` 或 `67%` 中最接近且满足副画面最小尺寸的比例。
- 双击分隔线恢复默认 `60%`。
- 按 `Esc` 取消当前拖动并恢复拖动前的比例。

拖动期间保持单画面控制层可见，结束或取消后恢复现有的 3 秒自动隐藏策略。

### 切换主直播间

点击副画面的主画面按钮后：

1. 系统找到当前主直播间和目标直播间在 `roomPlacementOrder` 中的位置。
2. 系统只交换这两个位置。
3. 系统把 `primaryRoomId` 更新为目标直播间。
4. 系统保留主画面比例、音频焦点、清晰度和弹幕设置。

例如当前槽位为 `[A, B, C, D]`，主直播间为 `A`。选择 `C` 后变为 `[C, B, A, D]`。随后选择 `B` 时变为 `[B, C, A, D]`。每次操作都只交换当前主画面和目标画面。

## 自动布局规则

主画面占据一侧的全部高度，副画面按直播间数量排列：

| 总直播间数 | 副画面排列 | 默认主画面比例 |
| --- | --- | --- |
| 1 | 无副画面 | 100% |
| 2 | 1 列 × 1 行 | 60% |
| 3 | 1 列 × 2 行 | 60% |
| 4 | 1 列 × 3 行 | 60% |
| 5–6 | 2 列 × 2–3 行 | 60% |
| 7–9 | 2 列 × 3–4 行 | 50% 或 60% |

布局引擎根据工作区实际尺寸过滤不可用吸附点：

- 主画面比例硬限制为 `42%–70%`。
- 副画面目标最小宽度为 240px，目标最小高度为 135px。
- 某个比例会让副画面小于目标尺寸时，系统不提供该吸附点。
- 窗口变小时，系统可以降低实际比例，但保留用户选择的偏好比例。窗口恢复后重新使用偏好比例。

副画面尺寸下限属于布局约束，不改变播放器内部的视频缩放方式。视频继续使用现有的等比显示策略。

## 状态模型

工作区增加两个持久化字段：

```ts
type PrimaryRoomRatio = 0.5 | 0.6 | 0.67;

interface WorkspaceState {
  roomPlacementOrder: string[];
  primaryRoomRatio: PrimaryRoomRatio;
}
```

组件内部维护拖动预览状态：

```ts
interface PrimaryResizePreview {
  startRatio: number;
  previewRatio: number;
  dragging: boolean;
}
```

- `roomPlacementOrder` 只控制直播画面槽位，不改变侧边栏房间顺序。
- 用户在侧边栏主动拖动房间顺序时，同时更新画面槽位顺序，保持现有行为。
- 添加房间时把新房间追加到 `roomPlacementOrder`。
- 删除房间时从 `roomPlacementOrder` 删除对应 ID。
- 切换分组或恢复工作区时，保留仍存在的 ID，并按房间列表顺序追加新 ID。
- 删除主直播间时，使用画面槽位中的下一间房作为新主直播间。

## 布局引擎

`layout-engine` 继续负责纯数据计算，不处理指针事件或 DOM。

主画面布局返回：

```ts
interface PrimaryFocusLayoutPlan {
  kind: 'primary-focus';
  primaryRoomId: string;
  orderedRoomIds: string[];
  secondaryColumns: 1 | 2;
  secondaryRows: number;
  preferredRatio: PrimaryRoomRatio;
  effectiveRatio: number;
  availableRatios: PrimaryRoomRatio[];
}
```

普通布局继续返回现有网格槽位。主画面布局根据 `roomPlacementOrder` 生成整数行列位置，主画面横跨所有副画面行。

## 渲染结构

所有 `RoomTile` 保持为 `.workspace-grid` 的直接子节点。分隔线也是同级网格元素。

主画面布局通过 CSS Grid 动态设置：

- 主画面轨道：`effectiveRatio`
- 分隔线轨道：8px
- 副画面轨道：剩余宽度内的 1 列或 2 列
- 行数：`secondaryRows`

该结构避免把主画面和副画面放进不同 React 容器。`RoomTile` 继续使用 `roomId` 作为 key，切换位置时 React 移动现有节点，不销毁播放器、弹幕连接或房间级状态。

## 组件职责

### `WorkspaceGrid`

- 读取布局、主直播间、槽位顺序和比例。
- 请求布局引擎生成布局计划。
- 把布局计划转换为 CSS Grid 变量和 `RoomTile` 槽位。
- 在主画面布局中渲染分隔线。

### `PrimaryRoomDivider`

- 处理 Pointer Events、pointer capture、键盘操作和取消操作。
- 使用 `requestAnimationFrame` 合并高频移动事件。
- 拖动时只更新本地预览比例。
- 松手时选择最近的可用吸附点并写入工作区状态。

### `workspace-store`

- 保存 `roomPlacementOrder` 和 `primaryRoomRatio`。
- 提供主画面槽位交换操作。
- 在房间增删、重排、分组切换和恢复持久化数据时校正槽位顺序。

### `workspace-persistence`

- 保存新增字段。
- 读取旧快照时使用房间顺序初始化 `roomPlacementOrder`，使用 `0.6` 初始化比例。
- 忽略不存在、重复或非法的房间 ID。
- 非法比例回退到 `0.6`。

## 无障碍与输入

分隔线使用 `role="separator"`，并提供：

- `aria-orientation`
- `aria-valuemin`
- `aria-valuemax`
- `aria-valuenow`
- 可见焦点样式

键盘操作：

- `ArrowLeft` / `ArrowUp`：切换到下一个更小的可用比例。
- `ArrowRight` / `ArrowDown`：切换到下一个更大的可用比例。
- `Home`：使用最小可用比例。
- `End`：使用最大可用比例。
- `Escape`：取消拖动或键盘预览。

系统在 `prefers-reduced-motion` 下关闭布局过渡。正常模式只对轨道变化使用短时过渡，拖动期间关闭过渡，保证分隔线紧跟指针。

## 异常处理

- 拖动期间删除主直播间：取消拖动，选择下一间房作为主直播间并重新计算布局。
- 拖动期间窗口尺寸变化：根据新尺寸重新计算边界并限制预览比例。
- 没有满足最小尺寸的吸附点：使用最接近默认值的安全比例，副画面允许低于目标尺寸但不得小于现有 CSS 的硬性最小值。
- `roomPlacementOrder` 与房间列表不一致：清除无效 ID、去重并追加缺失房间。
- 切换到非主画面布局：保留偏好比例，下次返回主画面布局时恢复。

## 测试范围

### 单元测试

- 1–9 路直播的副画面行列计算。
- 不同工作区尺寸下的可用比例过滤和有效比例计算。
- 主直播间连续切换时只交换两个槽位。
- 房间增删、重排和分组切换后的槽位顺序校正。
- 旧快照和非法快照的持久化回退。

### 组件测试

- 只有主画面布局显示分隔线。
- Pointer Events 拖动、吸附、取消和双击重置。
- 键盘调整和 ARIA 属性。
- 控制层自动隐藏与拖动锁定。

### UI 验证

- 1440 × 900 和 1920 × 1080 下验证 2–9 路布局。
- 验证窄窗口上下分割。
- 验证拖动期间没有文字、控件或画面重叠。
- 验证切换主直播间时播放器节点未重新创建，播放和弹幕不中断。

## 验收标准

1. 非主直播间没有尺寸拖动入口。
2. 主直播间拖动流畅，松手后落在可用吸附比例。
3. 副画面在剩余区域自动调整分布和大小。
4. 连续切换主直播间时，每次只交换当前主画面与目标画面的位置。
5. 切换位置和调整比例不会重建 `RoomTile`、播放器或弹幕连接。
6. 主画面比例和槽位顺序在重启后恢复。
7. 鼠标、触控板和键盘都能完成调整。
8. 房间增删、分组切换和窗口缩放不会产生无效槽位、重叠或不可操作的分隔线。

## 不在本次范围

- 任意直播间的二维自由缩放。
- 手动拖动副画面边界。
- 保存多套自定义比例预设。
- 每个分组使用独立主画面比例。
- 改变视频源分辨率或斗鱼清晰度选择逻辑。
