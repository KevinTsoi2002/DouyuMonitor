# 收藏主播状态监控与通知设计

## 目标

为收藏列表中的主播增加独立的轻量状态监控，使未加入当前播放画布的收藏房间也能检测开播、下播和直播间标题变化，并通过 Windows 通知准确指出主播身份。

## 范围

- 收藏房间独立于播放房间进行状态轮询。
- 监控字段：主播名、直播间标题、直播状态。
- 首次成功查询只建立基线，不发送通知。
- 状态变化通知：
  - `Offline -> Online`：`主播名 已开播`
  - `Online -> Offline`：`主播名 已下播`
- 在线期间标题变化通知：显示主播名、原标题和新标题。
- 收藏取消后停止监控并清理该房间基线。
- 保留现有通知去重和每分钟最多 6 条的限流规则。
- 新增“收藏标题变化”通知偏好；开播/下播继续使用现有偏好。

## 架构

新增 `FavoriteMonitor`，负责收藏集合同步、轻量查询调度、快照基线和变化事件生成。它复用现有 `RoomStatusScheduler` 的间隔、重试和抖动策略，但不创建 `RoomSession`、播放器或弹幕连接。

`AppController` 在收藏变化和服务响应边界同步监控器，将监控事件交给 `NotificationPolicy`。播放房间仍由 `MultiRoomCoordinator` 产生现有快照并走原通知链路；两条链路共享通知限流/去重规则，但各自维护状态基线，避免收藏监控影响播放。

## 数据流

1. `AppController` 从工作区快照读取所有 `favorite=true` 的房间及其已知元数据。
2. `FavoriteMonitor::synchronize()` 增删监控条目，并为新条目安排首次查询。
3. 服务返回搜索结果后，监控器更新主播名、标题和直播状态。
4. 首次成功结果只保存基线；后续结果生成 `FavoriteRoomOnline`、`FavoriteRoomOffline` 或 `FavoriteTitleChanged` 事件。
5. `NotificationPolicy` 执行统一去重和限流，`WindowsNotificationService` 根据偏好投递。
6. 监控结果同时更新工作区内收藏项元数据，使收藏列表即时显示最新主播名、标题和开播状态。

## 错误处理

- 查询失败不改变旧基线，不发送状态变化通知。
- 按现有 scheduler 重试退避；连续失败不产生重复通知。
- 房间从收藏列表移除时取消未完成请求并删除基线。
- 空主播名使用房间号作为通知主体；空标题显示“未命名直播间”。
- 应用恢复工作区时先完成基线建立，再允许变化通知，避免启动阶段误报。

## 测试要求

- `FavoriteMonitor`：首次基线、开播、下播、标题变更、取消收藏、失败重试。
- `NotificationPolicy`：新事件类型的内容、去重和限流；标题通知包含旧/新标题。
- `WindowsNotificationService`：收藏标题变化偏好关闭时不投递。
- `AppController`：收藏房间未加入画布时仍能触发通知并更新 `libraryRooms`。
- 回归运行现有 QML、控制器和 native self-test。

## 非目标

- 不为收藏监控创建视频解码、播放器或弹幕连接。
- 不改变当前播放房间的布局、清晰度、音频或弹幕行为。
- 不增加新的远程接口；继续使用现有房间搜索/状态查询服务。
