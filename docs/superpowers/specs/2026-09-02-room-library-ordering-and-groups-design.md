# 房间列表、收藏排序与多分组设计

日期：2026-09-02

## 目标

完善 Qt/QML 原生客户端的房间列表拖拽体验、紧凑房间卡片信息布局、收藏排序，以及分组管理能力。

本次范围的结果是：

- 房间列表拖动时有明确的插入位置提示，落下后列表立刻恢复整齐布局。
- 在窄尺寸直播画面中，主播、标题和状态文字不会侵入右侧操作按钮区域。
- 收藏默认按收藏时间排序，并可以在收藏视图内手动调整顺序；顺序在重启后保留。
- 一个房间可以属于多个分组；每个分组最多包含九个房间，并能作为独立工作区被激活。
- 分组管理界面可从已有房间库中选择成员，并保留成员移除、排序、重命名、删除与工作区切换能力。

## 非目标

- 不修改 libmpv 播放、音频焦点、弹幕、直播源解析和布局策略。
- 不重写 `RoomListModel`、`WorkspaceModel` 或引入 Electron、Chromium、WebEngine。
- 不改变预设的既有语义：预设仍保存其创建时的房间集合与工作区状态。

## 当前问题与根因

### 房间列表拖拽

`RoomSidebar.qml` 直接将拖动手柄的 `drag.target` 指向委托本身。放下时仅根据目标行调用 `moveRoom`，且释放时只复位 `x`，没有统一的插入落点状态或 `y` 复位。因此拖动过程无视觉指示，更新时可能短暂保留脱离列表流的委托位置。

### 紧凑房间卡片文字遮挡

`RoomTile.qml` 的顶部状态信息与右侧菜单按钮没有共享同一套剩余宽度约束。窄画面下文字宽度会越过操作区，导致标题或状态信息与按钮重叠。

### 收藏排序

`NativeRoomRecord` 只有 `favorite` 与 `lastOpenedAtMs`，没有收藏发生时间或稳定的手工排序值。收藏视图直接绑定整个房间库并以可见性过滤，无法满足独立排序与拖拽重排。

### 分组

现有逻辑已经支持分组创建、重命名、删除、成员增删、成员排序与激活，但：

- `assignRoomToGroup` 会将房间从所有其他分组移除。
- 分组管理窗口只能手工输入房间号，不能直接从房间库选择。
- 成员容量、候选房间的已加入状态和操作反馈不明确。

用户已确认同一直播间可加入多个分组。

## 设计

### 1. 房间列表拖拽与自动对齐

在 `RoomSidebar.qml` 的 `ListView` 范围维护拖拽会话状态：源房间 ID、候选插入索引与拖动是否激活。

- 每个委托根据鼠标相对中线判断“插入到当前项之前或之后”。
- 当可接受的拖拽进入时，目标委托显示一条高对比度的细插入线；源委托降低不透明度。
- 放下时，QML 将源房间和归一化后的目标索引传给 C++。
- C++ 在实际顺序上执行一次移动并重新发布快照；QML 在释放、取消、完成后清除插入状态，并将拖动委托的 `x`、`y` 同时复位。
- 键盘/按钮的上移、下移继续调用现有相对移动接口，保持兼容。

为避免拖动时把 QML 的临时像素位置当成数据顺序，最终顺序永远以 C++ 协调器发布的房间顺序为准。

### 2. 紧凑房间卡片信息布局

顶部栏拆分为左侧元信息区域和固定宽度的右侧操作区。

- 右侧操作区始终保留菜单按钮及边距所需宽度。
- 左侧区域的分类、观看人数等文字在可用宽度内右省略，优先保留直播状态标签。
- 不允许文本越出左侧容器；极窄尺寸下隐藏优先级最低的次级文字，而非压缩到操作区。
- 底部主播名和标题继续基于可用宽度省略，且不改变播放器、弹幕与悬浮菜单层级。

### 3. 收藏时间与手动顺序

为 `NativeRoomRecord` 增加两个持久字段：

- `favoriteAddedAtMs`：当前收藏周期开始的 Unix 毫秒时间；未收藏时为 `0`。
- `favoriteSortOrder`：收藏列表内的稳定人工排序键；未收藏时为 `0`。

收藏规则：

- 首次收藏或取消后再次收藏时，写入当前时间并分配新的排序键。
- 取消收藏时清空两个收藏字段。
- 收藏页以仅收藏房间的独立派生列表作为模型；默认按收藏时间降序排列。
- 用户在收藏页拖拽后，控制器重新写入连续的人工排序键；从此该手工顺序优先于默认时间顺序。
- 收藏页的拖拽交互复用房间列表的插入提示模式，但不影响当前播放房间的顺序。

持久化版本升级至新版本。读取旧版本时，已有收藏按其原有库顺序生成稳定排序键，并以 `lastOpenedAtMs`（若存在）作为兼容的收藏时间回退；所有非收藏房间的新增字段为零。保存后使用新版本格式，且不保存任何播放源、Cookie、签名或其他敏感数据。

### 4. 多分组工作区

分组为可复用的房间集合，而不是房间的唯一分类。

- 分配房间到一个分组时，仅在目标分组中去重后追加，不再移除其他分组中的同一房间。
- 每个分组独立保持成员顺序，最多九个成员；达到上限时拒绝新增并返回明确提示。
- 激活分组时，当前工作区替换为该组成员；分组可以为空，空组激活后展示空工作区。
- 移除成员只影响当前所选分组；删除分组不删除房间库记录。
- 若删除当前激活的分组，活动分组 ID 清空，已在播放的当前工作区保持不被强制清空。
- 预设引用已删除分组时继续按已有清理规则将该引用置空。

房间展示层不再把分组关系建模为单一 `groupId`。需要展示时，以组 ID 列表或已格式化组名列表表达多重归属；本次不在紧凑房间卡片新增额外标签，避免挤占现有信息空间。

### 5. 分组管理界面

`GroupManagerDialog.qml` 调整为三个区域：

1. 分组列表：选择、创建、重命名、激活和删除，显示成员数量，例如 `3 / 9`。
2. 当前分组成员：显示头像/名称，支持移除与上移/下移；空分组显示明确空状态。
3. 房间库：按已加入和未加入状态列出可分配房间，点击添加；已加入项禁用或显示已加入状态。保留房间号输入作为快速定位/过滤，而不是唯一添加方式。

所有命令错误会回显到对话框内的简短状态提示，成功操作后刷新可选项和计数。窗口关闭不会丢失已成功持久化的更改。

## 数据与接口调整

- `NativeRoomRecord`、`NativeWorkspaceStore`：新增收藏字段、JSON 序列化、反序列化、兼容迁移和归一化。
- `AppController`：补充收藏重排接口；更新收藏切换逻辑；移除唯一分组归属行为；在分组容量溢出时返回错误。
- `RoomListModel`：保持当前播放房间顺序职责，不承载收藏视图的排序。
- `RoomLibraryView`：新增收藏专用派生数据和拖拽排序调用。
- `RoomSidebar.qml`：新增房间列表插入标记与统一拖拽复位。
- `RoomTile.qml`：重构顶部信息区的锚定关系和文字省略规则。
- `GroupManagerDialog.qml`：改为库内成员选择和状态反馈界面。

## 验收标准

1. 拖动房间时，列表能显示唯一且正确的插入线；放下、取消后所有项自动贴合，未残留偏移。
2. 房间卡片在最小支持尺寸下，顶部文本不与右侧按钮重叠；长分类/观看人数会省略或隐藏。
3. 新收藏按收藏时间显示；拖拽调整后顺序可重启恢复；取消后不再出现在收藏页，再收藏会进入新的顺序位置。
4. 同一房间可同时加入两个以上分组，各组顺序独立、持久化后不丢失；单组不超过九个成员。
5. 分组管理窗口可从房间库将成员加入或移出选中分组，能显示容量与结果状态。
6. 现有房间增删、分组切换、预设、音频与播放流程的测试继续通过。

## 验证策略

- 先写并观察失败的单元测试：收藏迁移/排序、收藏重排、多分组成员关系、容量限制与当前分组更新。
- 补 QML 交互测试：插入标记状态、拖拽结束复位、收藏排序控件、房间卡片窄宽文本区域、分组房间库选择。
- 使用 CMake/CTest 运行受影响测试与原生测试集，并构建 Debug 与 Release 目标。
- 对可运行的视觉验证页使用 Playwright 截图核查；原生 QML 窗口同时依赖 Qt Quick 交互测试验证，若本机没有可供 Playwright 连接的视觉页，会明确记录这一限制而不虚构浏览器验证。
