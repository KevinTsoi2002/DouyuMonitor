# 工作区预设实现计划

> **执行约定：** 开始实现前按 `executing-plans` skill 逐项执行；每个行为先补一个可失败的测试，再写最小实现并复跑相关测试。

## 目标与边界

为多直播间监看工作区增加可命名、可持久化、可切换的预设。预设是当前工作区的用户配置快照，不保存播放源 URL、签名参数、Cookie、运行时错误或播放检查诊断。加载预设必须以预设房间为准，但不能破坏历史、收藏、分组或其他预设。

## 1. 数据模型与持久化迁移

### 1.1 类型定义

- 在 `src/renderer/store/workspace-persistence.ts` 或相邻的 Store 类型模块定义并导出 `WorkspacePreset` 与 `WorkspacePresetRoom`。
- 房间快照仅包含房间元数据、在线状态、布局所需状态、清晰度、音量和弹幕开关。
- 为 `WorkspaceSnapshot` 增加 `workspacePresets` 与 `activeWorkspacePresetId`；将 `WORKSPACE_SCHEMA_VERSION` 从 4 升为 5。
- 为 `WorkspaceState` 增加预设集合、当前预设 id、保存/更新/加载/重命名/删除方法及可供 UI 展示的未保存变化状态或计算方法。

### 1.2 解析与迁移

- 把 v1/v2/v3/v4 读取逻辑保持兼容；v4 迁移时预设列表为空、当前预设 id 清空。
- 新增预设解析器：校验 id、名称、时间、房间字段、`roomOrder`、布局、比例、音频房间、弹幕设置和治理覆盖；不完整或非法条目单项过滤，不让整个工作区读取失败。
- 规范化预设名称：去除首尾空白、拒绝空值、限制 40 个字符；解析时丢弃重复 id 或重复名称。
- 限制最多 20 个预设，持久化读取和写入都截断/拒绝越界数据。
- 对治理覆盖复用现有 `parseDanmakuGovernanceSettings` 规则；只保留预设房间对应的覆盖。
- 增加持久化测试：schema v5、v4 迁移、预设字段 round-trip、非法条目过滤、名称和数量限制。

## 2. 规范化快照与 Store 行为

### 2.1 快照与未保存指纹

- 在 Store 内增加 `createWorkspacePresetSnapshot(state)`，按 `roomOrder` 保持房间顺序，并补上遗漏的房间。
- 快照只取用户可控字段：房间元数据/质量/音量/弹幕开关、布局、主房间、主房间比例、音频焦点、全局弹幕/静音、全局弹幕设置、治理覆盖。
- 增加稳定的规范化指纹函数，排序对象键和治理覆盖键，比较 JSON 结果；忽略在线状态变化、播放源、错误、检查时间和恢复诊断。
- 当前预设存在时以当前工作区指纹和预设指纹比较，暴露 `hasUnsavedWorkspaceChanges`（或等价选择器）；未保存工作区始终视为有变化但不阻止普通操作。

### 2.2 保存、更新、重命名、删除

- `saveWorkspacePreset(name)`：校验名称唯一性和 20 项上限，生成 UUID 与时间，保存当前快照，设为当前预设，持久化并返回 id；失败返回 `undefined`，不改变状态。
- `updateWorkspacePreset(id)`：仅更新现有预设的快照与 `updatedAt`，保持创建时间和名称；成功后当前预设指向该 id。
- `renameWorkspacePreset(id, name)`：校验目标存在、名称有效且不与其他预设重复；只更新名称和更新时间。
- `deleteWorkspacePreset(id)`：删除目标预设；若删除当前预设，只清空当前预设 id，保留房间库、历史、收藏、分组和当前房间。
- 每次成功变更都走现有工作区持久化路径，确保崩溃前不会留下内存与磁盘不一致的半状态。

### 2.3 预设加载事务

- `loadWorkspacePreset(id)` 先读取并验证目标预设，生成完整的 next state 草稿；任何校验或恢复异常都返回 `false` 并保持加载前状态。
- 目标房间按 `roomOrder` 排列，再补齐快照中有但顺序数组遗漏的房间；限制 `RoomRegistry.MAX_ROOMS`。
- 直接重建当前 `rooms` 与 `roomLibrary` 条目，不调用普通 `addRoom`，避免重复写入历史。
- 恢复布局、主房间、主画面比例、音频焦点、房间显示设置、全局弹幕设置和治理覆盖；主房间/音频房间不存在时按现有安全回退规则处理。
- 清理当前工作区中不在预设的活动房间，但保留房间库中独立记录以及历史、收藏、分组。
- 恢复房间的运行时状态统一置为现有检查流程可接受的初始状态；仅对在线房间触发 metadata/playback 检查，未开播房间不探测播放源，阻塞/失败房间继续留在当前工作区。
- 成功后设置 `activeWorkspacePresetId`，持久化并返回 `true`；不修改其他预设内容。
- 增加 Store 测试：保存/更新/加载/重命名/删除、同名校验、上限、未保存指纹、恢复已移除房间、失败检查保留房间、恢复异常回滚。

## 3. 顶栏入口与预设抽屉

### 3.1 组件结构

- 新增 `WorkspacePresetPanel.tsx`，沿用现有弹幕设置/监控状态面板的抽屉、Escape 和外部点击模式。
- 在 `AppHeader.tsx` 增加独立“工作区”按钮，显示当前预设名或“未保存工作区”，提供 `aria-expanded`、`aria-controls`、tooltip；打开时关闭其他顶栏面板。
- 预设列表项显示名称、房间数、布局短名和更新时间；当前项高亮并显示未保存变化提示。
- 空状态提供直接保存入口；列表状态提供保存当前、更新当前、加载、重命名、删除操作。

### 3.2 交互与错误处理

- 保存/重命名使用轻量表单或内联编辑，展示名称错误、重复名称和 20 项上限错误。
- 加载当前预设前检查未保存指纹；有变化时显示确认提示，取消不改变当前工作区。
- 加载成功关闭面板并显示结果提示；失败保留当前面板和当前工作区，显示可理解的错误原因。
- 删除当前预设回到未保存工作区，不询问删除房间数据；非当前预设删除需要确认。
- 面板固定宽度并使用窄屏布局，保证 1280px 与 390px 下不横向溢出；按钮、表单和列表项具备键盘可达性。
