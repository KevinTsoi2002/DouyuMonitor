# DouyuMonitor 现代深色 UI 改造设计规格

日期：2026-09-05  
适用版本：V0.2.3 及后续版本  
目标平台：Windows x64 / Qt Quick + QML + C++

## 1. Design Read

Design Read: Windows 桌面端多路直播监控工作台 for 长时间值守与快速切换用户；vibe = 现代、克制、清晰、专业；assets = 现有 `douyu_monitor.svg`、房间头像、直播画面与状态数据；constraints = 无 Electron、最多 9 路、无边框窗口、QML 原生交互。

设计参数：

- `DESIGN_VARIANCE = 4`：保留现有工作台结构，仅统一层级与控件表达。
- `VISUAL_DENSITY = 7`：在单个视口内高效呈现房间、状态和多路画面。
- `MOTION_INTENSITY = 3`：仅保留悬浮、选中、抽屉和状态变化反馈。

## 2. 设计目标

1. 管理区与播放区统一为深色，但使用不同明度区分工作区域。
2. 直播画布为第一视觉焦点，房间库为持续可见的第二焦点。
3. 图标从图形上可区分作用，尤其是最大化与全屏播放。
4. 主播名、直播标题、在线状态和动作按钮在任何长度下都不重叠。
5. 现有功能与交互入口保持不变，视觉重构不改变业务逻辑。

## 3. 页面结构

### 3.1 顶部应用栏

- 左侧顺序：房间列表按钮、程序图标、产品名称。
- 程序图标使用 `native/app/assets/douyu_monitor.svg`，不再使用字母占位符。
- 中部保留可拖拽标题区域。
- 右侧顺序：弹幕设置、监控状态、工作区预设、布局、声音总控、全屏播放、最小化、最大化、关闭。
- 所有图标按钮使用固定尺寸，不因文本或窗口宽度改变。

### 3.2 窗口控制语义

- 最小化：横线图形。
- 最大化/还原：单一闭合方框，表达窗口边界扩大或恢复。
- 全屏播放：四个分离角标，表达内容向屏幕四周扩展；不使用闭合方框。
- 关闭：X 图形，悬浮时使用红色危险态。
- 最大化和全屏必须使用不同 SVG 资源、不同 `Accessible.name` 与不同 tooltip。

### 3.3 左侧房间库

- 背景使用深蓝灰管理表面，播放区使用更深的画布表面。
- 顶部显示“房间库”和当前路数，例如 `5 / 9 路`。
- 保留输入房间号/链接、添加按钮、当前/收藏/历史三段式切换。
- 房间条目采用固定高度两级信息：主播名一行、标题一行；状态作为第三行低权重元信息。
- 标题和主播名使用省略号，动作区保持独立固定宽度，不允许被文本挤压。
- 在线状态使用绿色状态点 + “直播中”，离线使用中性状态点 + “未开播”，异常使用橙红色状态点。
- 选中房间通过表面明度和橙色细边表达，不依赖粗重高亮框。

### 3.4 主播放画布

- 保留自动布局与主直播间布局。
- 直播卡片统一使用深色画布、11px 左右圆角、低强度阴影。
- 主直播间通过更宽区域、橙色细边和“主画面”标签表达。
- 卡片顶部显示状态徽标与路数，底部显示主播名、标题和操作按钮。
- 房间标题必须具备最大宽度和 `Text.ElideRight`，按钮区不参与文本伸缩。
- 卡片操作图标固定为：设为主画面、声音焦点、弹幕、更多/刷新；每个动作只对应一个图形。

### 3.5 底部状态栏

- 显示直播中数量、未开播数量、弹幕连接数、声音焦点和静默检查状态。
- 状态栏使用独立深色表面和分隔线，不弹出干扰性通知。

### 3.6 监控、弹幕、预设与声音面板

- 统一采用深色 Drawer/Popup 表面、12px 圆角、单一关闭按钮和一致内边距。
- 面板标题、辅助说明、内容分组和操作按钮使用统一层级。
- 声音总控、弹幕设置和监控状态均使用明确的面板标题，不在按钮下方漂浮成无边界控件。
- 关闭按钮必须位于面板右上角且可点击，点击外部不应误触发主画布操作。

## 4. 视觉令牌

### 4.1 颜色

- 应用栏：`#11151B`
- 管理区：`#1B2028`
- 播放画布：`#171B22`
- 控件表面：`#202731`
- 输入/井面：`#12171E`
- 边框：`#303845` / `#344252`
- 主文字：`#EEF2F7`
- 次文字：`#8996A6`
- 品牌与关键动作：`#F27522`
- 在线状态：`#50CF91`
- 警告状态：`#F0B26C`
- 关闭危险态：`#D78383`

颜色仅用于层级与状态，不使用大面积渐变或装饰性光斑。

### 4.2 尺寸与间距

- 顶栏高度：`52-56px`。
- 普通图标按钮：`28-32px`。
- 房间条目：`56-64px` 固定高度。
- 控件圆角：`6-12px`，卡片不超过 `12px`。
- 主间距：`8px`；分组间距：`12-16px`。
- 可操作目标不低于 `28px`，高频列表操作不低于 `32px`。

## 5. 图标规范

新增或整理以下 SVG 资源：

- `window-maximize.svg`：闭合方框。
- `window-fullscreen.svg`：四角分离角标。
- `window-minimize.svg`：横线。
- `window-close.svg`：X。
- `sidebar-toggle.svg`、`message-circle.svg`、`activity.svg`、`star.svg`、`layout-grid.svg`、`volume-2.svg`、`more-horizontal.svg` 等保持单一语义。

禁止使用 Unicode 字符替代窗口控制图标；禁止让最大化和全屏共用同一资源。

## 6. 状态与错误表现

- 加载：使用状态点和短文本，避免空白卡片。
- 未开播：保留主播信息和标题，画面区域显示中性占位。
- 播放异常：在卡片内显示“重新检查播放源”动作，不弹出持续 toast。
- 弹幕异常：使用连接状态点和重试动作。
- 空房间库：显示“把直播间放进同一张画布”和添加房间动作。

## 7. 技术边界

- 仅修改 QML 视觉层、图标资源和必要的可访问性属性。
- 不引入 Electron、Chromium、Qt WebEngine 或新的运行时依赖。
- 不改变 `AppController`、房间模型、播放协调器和状态调度器的业务协议。
- 继续使用现有 `RoomSidebar`、`RoomTile`、`WorkspaceGrid`、`AppHeader`、Drawer/Popup 组件边界。

## 8. 验证方案

1. QML 引擎和交互测试：窗口控制按钮、tooltip、无边框拖拽、面板关闭。
2. 视觉截图：1280×720、1600×900、1920×1080。
3. 房间标题长文本：确认不覆盖操作按钮。
4. 1、2、5、8、9 路布局：确认画布填满且主次层级清晰。
5. 全屏与最大化：确认状态、图标和窗口行为不同。
6. 构建产物：确认不新增 Electron/Chromium/WebEngine 文件。
