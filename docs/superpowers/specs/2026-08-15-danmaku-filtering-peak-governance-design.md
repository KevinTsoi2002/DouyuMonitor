# 弹幕筛选与高峰治理设计

日期：2026-08-15

## 目标

为多直播间弹幕增加关键词筛选、重复弹幕抑制和自适应高峰治理，同时保留连续飘屏体验。用户可以使用全局默认规则，也可以为单个房间覆盖规则，并在设置面板查看当前治理效果。

## 已确认的产品决策

- 设置入口采用分组页签：显示、治理、统计。
- 规则作用域采用“全局默认 + 房间覆盖”。房间覆盖字段完整替换对应的全局字段，清除覆盖后恢复继承。
- 关键词使用普通包含匹配。系统清理首尾空白并做大小写归一化，不支持正则表达式。
- 重复抑制比较相邻的相同文本，默认窗口为 3 秒，允许调整为 1–10 秒。
- 高峰治理使用自动三级策略：正常、拥挤、爆发。
- 统计同时提供近 60 秒速率和当前运行会话累计数量。
- 规则只影响 renderer 层的弹幕接收和排队，不改变斗鱼连接、播放和重连流程。

## 用户体验

### 显示页签

保留现有速度、字号、不透明度、区域、密度、字体和渲染模式设置。现有连续飘屏逻辑保持不变，用户不会再看到固定数量的弹幕上限。

### 治理页签

面板顶部提供作用域选择：

- 全局默认
- 指定房间

治理控件包括：

- 治理总开关
- 关键词黑名单输入和标签列表
- 重复抑制窗口滑块，范围 1–10 秒
- 高峰保护开关
- 房间作用域下的“继承全局”和“保存房间覆盖”操作

关键词最多保存 50 个，每个关键词最多 40 个字符。空白项、重复项和超出限制的项不会进入持久化数据。

### 统计页签

统计页展示当前作用域对应的房间或全局汇总：

- 当前治理级别：正常、拥挤或爆发
- 近 60 秒速率
- 最近峰值速率
- 关键词过滤数量
- 重复抑制数量
- 高峰限流数量
- 队列淘汰数量

统计提供清零按钮。统计只存在当前运行会话内，不写入本地存储，也不保存弹幕文本。

## 治理规则

系统按以下顺序处理每条消息，每条消息只计入一个治理原因：

1. 关键词过滤：将消息文本和关键词规范化后做包含匹配。命中任意关键词时丢弃并计入关键词过滤。
2. 重复抑制：对通过关键词检查的消息，若与上一条相同文本在配置窗口内相邻出现，则丢弃并计入重复抑制。
3. 高峰限流：根据房间最近 3 秒的输入速率选择治理级别，并按级别放行消息。
4. 队列保护：通过治理的消息进入现有 pending 队列。队列超过 300 条时淘汰最旧消息，计入队列淘汰。

高峰策略：

| 级别 | 最近 3 秒输入速率 | 放行上限 |
| --- | ---: | ---: |
| 正常 | ≤ 10 条/秒 | 不额外限流 |
| 拥挤 | 11–30 条/秒 | 20 条/秒 |
| 爆发 | > 30 条/秒 | 10 条/秒 |

限流保留后续到达的最新消息。现有上游 dropped 数量继续保留并与本地治理统计分开记录，避免把平台丢弃和本地策略混为一谈。

## 数据模型

### 治理设置

在 `src/renderer/danmaku/danmaku-settings.ts` 增加：

```ts
interface DanmakuGovernanceSettings {
  enabled: boolean;
  keywordBlacklist: string[];
  duplicateWindowSeconds: number;
  peakProtectionEnabled: boolean;
}
```

`DanmakuSettings` 增加 `governance: DanmakuGovernanceSettings`。默认值为：治理开启、关键词为空、重复窗口 3 秒、高峰保护开启。

工作区增加：

```ts
danmakuGovernanceOverrides: Record<string, Partial<DanmakuGovernanceSettings>>;
```

房间覆盖只保存有效字段。治理 store 将全局值与对应房间覆盖合并后运行。

### 房间治理状态

`DanmakuRoomView` 增加治理统计：

```ts
interface DanmakuGovernanceStats {
  level: 'normal' | 'crowded' | 'burst';
  recentRate: number;
  peakRate: number;
  filtered: number;
  duplicates: number;
  rateLimited: number;
  queueOverflow: number;
  upstreamDropped: number;
}
```

store 内部为每个房间保存近 60 秒的时间戳、最近通过关键词检查的文本及时间、当前会话统计。统计不通过 React props 传递，组件通过 selector 读取。

## 模块与数据流

### 治理引擎

创建 `src/renderer/danmaku/danmaku-governance.ts`，提供纯函数：

- 规范化和校验治理配置
- 计算最近输入速率和治理级别
- 处理一批弹幕并返回通过列表、原因计数和下一次治理状态

该模块不依赖 React、Zustand、Electron 或网络连接，可以用固定时间戳直接测试。

### 弹幕 store

`src/renderer/store/danmaku-store.ts` 在进入 pending 队列前调用治理引擎。`syncRoom` 接收可选的有效治理配置；配置变化时清理不再适用的待处理消息，但保留房间连接状态。禁用弹幕或移除房间时清理治理状态和统计。

store 继续维护现有 ID 去重窗口和 300 条队列上限。`dropped` 继续表示上游丢弃与队列溢出的总量，新统计字段提供可拆分的治理原因。

### 弹幕 context

`src/renderer/store/danmaku-context.tsx` 从工作区读取全局治理设置和房间覆盖，为每个房间解析有效配置并同步给弹幕 store。弹幕连接生命周期保持当前条件：只为在线、开启弹幕且全局弹幕开启的房间建立连接。

### 工作区持久化

`src/renderer/store/workspace-persistence.ts` 将快照版本从 3 升到 4，增加 `danmakuGovernanceOverrides`。版本 1–3 的数据迁移为空覆盖并使用默认治理设置。非法治理字段使用解析器默认值，不能使整个工作区加载失败。

`src/renderer/store/workspace-store.ts` 增加全局治理更新、房间覆盖更新和清除覆盖的 action，并在所有更新后复用现有持久化路径。

## 错误处理与安全边界

- 关键词和治理配置在解析、编辑、持久化三个入口都限制数量、长度和数值范围。
- 治理引擎遇到异常输入时跳过该条消息，不阻断同批次其他消息。
- 统计只保留数字和级别，不记录弹幕文本、播放地址、token、cookie 或原始上游错误。
- 治理限流不会触发弹幕连接重试，也不会改变播放失败恢复逻辑。
- 房间离线或关闭弹幕后不继续搜索播放源，沿用现有状态刷新边界。

## 测试与验收

### 单元测试

创建 `tests/danmaku-governance.test.ts`，覆盖：

- 关键词归一化、去重、数量和长度限制
- 包含匹配和大小写归一化
- 3 秒重复抑制及窗口边界
- 正常、拥挤、爆发三级判断
- 各级放行上限和限流计数
- 统计的近 60 秒速率、峰值和分类计数

### store 和持久化测试

扩展 `tests/danmaku-store.test.ts`，覆盖全局配置、房间覆盖、配置更新、队列淘汰、禁用清理和上游 dropped 分离。

扩展 `tests/workspace-persistence.test.ts` 与 `tests/workspace-store.test.ts`，覆盖快照版本 4、旧版本迁移、非法覆盖回退、全局更新、房间覆盖和清除继承。

### 组件测试

扩展 `tests/danmaku-settings-panel.test.tsx`，覆盖三个页签、作用域切换、关键词提交、继承全局和统计清零。

### 运行验收

完成实现后运行：

```text
npm test
npm run typecheck
npm run build
```

再用浏览器检查桌面和窄屏设置面板，确认页签切换、输入控件、统计内容无溢出，且高峰时弹幕仍持续滚动而不是固定只显示少量消息。

## 非目标

- 不实现正则表达式、用户白名单、跨设备同步或云端统计。
- 不修改斗鱼协议解析、播放源签名和 Electron 主进程连接逻辑。
- 不把治理统计写入历史记录或工作区快照。
