# DouyuMonitor 完整 QML 视觉迁移设计

日期：2026-09-05  
适用范围：Qt Quick/QML 主界面，Windows x64，V0.2.3 后续开发版本

## 目标

将现有“基础深色工作台”迁移为完整的现代深色多路直播监控界面。迁移后的实际 Qt 程序以已确认的对照基准为目标，不再把浏览器展示稿当作已实现界面。

现有 C++ 播放、房间管理、预设、弹幕、通知、音频和布局协议保持不变。QML 继续通过现有 `AppController`、房间模型和工作区模型调用业务能力。

## 已确认的产品状态

### 空工作区

- 保留完整的应用栏、房间库、画布和底部状态栏。
- 画布只显示一个明确的添加入口、简短说明和九路上限提示。
- 不渲染虚构的主播、标题或直播卡片。
- 底部状态栏显示零直播、零未开播、弹幕未连接和无声音焦点。

### 已加入直播间的工作区

- 房间库显示当前路数，例如 `3 / 9 路`。
- 每个房间条目显示头像、主播名、直播标题和直播状态。主播名与标题在固定动作区前省略。
- 播放画布按现有自动布局或主直播间布局渲染真实卡片。
- 卡片显示路数、直播状态、主画面标记、主播名、标题与固定动作区。
- 底部状态栏显示直播中数量、未开播数量、弹幕连接数、声音焦点和静默检查状态。

### 尺寸

- 顶栏固定为 `52px`。
- 高频图标按钮采用 `32px` 点击区域，图标居中且不以文字替代。
- 房间条目固定为 `60px` 高度。
- 卡片圆角使用 `9px` 到 `11px`，面板圆角使用 `11px`。
- 基础间距为 `8px`，分组间距为 `12px` 到 `16px`。

## 交互规则

- 顶栏按功能分组：弹幕、监控、预设、布局、声音、全屏和窗口控制。
- 所有图标按钮都有 tooltip 与 `Accessible.name`。最大化图标使用闭合方框；全屏使用四个分离角标。
- 卡片和房间条目的文字区不能伸入动作区。主播名和直播标题使用 `Text.ElideRight`。
- 浮层在右上角提供关闭按钮。声音总控、弹幕设置和监控面板采用同一容器层级。
- Toast 不用于正常播放状态轮询。正常状态检查保持静默。
- 全屏播放、窗口最大化、布局切换和声音模式继续调用现有业务入口。

## 非目标

- 不替换 Qt Quick/QML 或引入 Electron、Chromium、Qt WebEngine。
- 不修改直播拉流、libmpv、斗鱼接口、弹幕协议、收藏排序和预设持久化的业务语义。
- 不为了填满空工作区添加模拟直播数据。

## 验收标准

### 自动化回归

- QML 模块启动路径加载 `Theme` 单例，窗口、侧栏、卡片和浮层获得正确令牌颜色。
- 窗口控制测试确认最大化与全屏使用不同资源、名称和行为。
- 长主播名、长标题的文字矩形不与固定动作区相交。
- 空工作区与有 1、3、5、9 路房间的对象层级、底部状态栏和布局边界可被 QML 测试验证。
- 既有房间、预设、音频、弹幕和关闭回归测试继续通过。

### 真实窗口视觉验证

- 使用真实 Qt 原生窗口截图，而非浏览器示意图，分别检查 `1280x720`、`1600x900` 和 `1920x1080`。
- 检查空工作区、1 路、3 路、5 路和 9 路画布。
- 检查长标题、房间库折叠、声音总控、弹幕面板、预设面板、最大化和全屏。
- 截图对照确认没有黑屏、文本重叠、裁切按钮、漂浮在错误层级的面板或缺失图标。

## 实施顺序

1. 补齐 `Theme.qml` 令牌并建立 QML 颜色与可访问性回归。
2. 重构主壳层、顶栏、窗口控制和底部状态栏。
3. 重构房间库与当前/收藏/历史列表条目。
4. 重构画布、空状态、直播卡片和主画面层级。
5. 统一 Popup、Drawer、Dialog 与 Toast。
6. 执行自动化回归和多分辨率原生窗口截图验证，逐项修正可见差异。
