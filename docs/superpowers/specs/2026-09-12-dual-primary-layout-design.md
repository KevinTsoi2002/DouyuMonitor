# 双主直播间布局设计

## 目标

为工作区增加“双主直播间”布局：当活动直播间达到 4 路或以上时可启用，最多显示 10 路；两个指定主直播间占据最大的区域。

## 行为

- 新布局使用既有布局 ID `primary-two`，菜单名称为“双主直播间”。
- 布局切换在 QML 菜单和 C++ 控制器中都校验活动房间数不少于 4 路。
- 活动房间数降到 3 路或更少时，自动切回 `auto`，并在工作区状态栏提示“双主布局至少需要 4 路直播间”。
- 活动房间上限、分组房间上限和预设房间上限从 9 路提升为 10 路。

## 主画面选择

- 保留现有 `primaryRoomId` 作为主画面 1。
- 新增 `secondaryPrimaryRoomId` 作为主画面 2，并纳入协调器、工作区模型、快照、预设及 JSON 持久化。
- 双主模式房间菜单提供“设为主画面 1”和“设为主画面 2”；当前房间显示对应状态。
- 单主模式继续使用原“设为主画面”操作，不改变旧配置行为。
- 删除主画面 1 后由剩余列表第一路补位；删除主画面 2 后由第一路不同于主画面 1 的剩余房间补位。房间不足 4 路时先执行自动切回。

## 布局几何

- 主画面 1、主画面 2 在上方并列，宽度相等且高度最大。
- 其余房间在下方排列，按总路数固定为：4 路 2 个、5 路 3 个、6 路 4 个、7 路 5 个、8 路 6 个、9 路 7 个、10 路 8 个。
- 主画面 1 和主画面 2 都参与现有高画质优先级策略。
- 无效或缺失的第二主 ID 自动从活动房间中补齐，且不会与第一主重复。

## 兼容性

- 旧版本只含 `primaryRoomId` 的快照和预设继续可加载，第二主为空时按单主逻辑处理。
- 非法布局 ID 仍归一化为 `auto`。
- 现有单主布局的几何、质量、菜单和持久化行为保持不变。

## 测试

- 协调器测试覆盖双主选择、两主质量优先、删除补位和低于 4 路自动切回。
- 工作区存储测试覆盖第二主 ID 的保存、加载、校验及旧 JSON 兼容。
- QML 交互测试覆盖布局菜单的启用条件、双主菜单项和 4–10 路几何结果。
