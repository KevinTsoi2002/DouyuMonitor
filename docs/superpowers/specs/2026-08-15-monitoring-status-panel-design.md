# 监控状态面板设计

## 目标

用户通过顶栏入口打开右侧状态抽屉，查看所有活动直播间的直播、播放和弹幕健康状态，并对异常房间执行刷新或重试。抽屉覆盖工作区，不改变直播布局，不重新挂载播放器或弹幕会话。

## 界面

- 顶栏增加 Activity 图标按钮，按钮显示异常总数提示。
- 桌面端面板固定在顶栏下方右侧，宽度 420px，高度不超过可用视口。
- 移动端面板左右各留 8px，占用顶栏下方可用宽度。
- 面板顶部显示在线、播放中、播放异常、弹幕异常四项汇总。
- 房间列表采用紧凑行布局，不嵌套卡片。每行显示主播名称、房间号、直播状态、播放状态、最近检查时间、自动恢复次数、弹幕状态和最近错误类型。
- 在线房间提供刷新播放源按钮；弹幕失败时提供重试按钮。
- 空工作区显示简短空状态。

## 状态模型

RoomSession 增加非持久化字段：

- `playbackCheckedAt`：最近一次播放源检查完成时间。
- `playbackRecovery`：播放器恢复次数、是否耗尽、错误代码和更新时间。

WorkspaceStore 增加 `reportPlaybackRecovery(roomId, diagnostic)`，只更新目标房间的运行时状态。`refreshStreamAvailability` 开始时清空旧恢复状态，成功时记录上游 `checkedAt`，失败时记录本地完成时间。

播放恢复控制器通过 RoomPlaybackSurface 回调上报状态。播放恢复成功、手动刷新或房间移除后清除状态。运行时字段不写入 workspace 快照。

## 汇总规则

- 在线：`room.online` 且状态不是 `offline`。
- 播放中：在线、播放源可用且没有恢复中的播放器错误。
- 播放异常：在线房间处于平台阻塞、播放源检查失败、自动恢复中或自动恢复耗尽。
- 弹幕异常：状态为 `failed` 或 `platform-blocked`。
- `checking` 和 `connecting` 属于进行中状态，不计为异常。

## 性能

- 面板汇总使用纯函数计算 Workspace 房间状态。
- 弹幕异常总数订阅 primitive 数值，房间行只订阅目标房间的 DanmakuStatus。
- 面板不订阅 pending 弹幕数组，弹幕滚动不会触发整个状态面板重渲染。

## 可访问性

- 顶栏按钮提供 `aria-expanded` 和 `aria-controls`。
- 抽屉使用 `role="dialog"` 和可见标题。
- Escape 关闭面板，刷新和重试图标均提供中文 `aria-label` 与 `title`。

## 验收

- 汇总、状态映射、错误优先级和时间格式有单元测试。
- WorkspaceStore 测试覆盖检查时间和恢复诊断的写入、清除及房间隔离。
- 面板组件测试覆盖汇总、房间详情、空状态和异常操作。
- 桌面与移动视口没有裁切、重叠或横向溢出，控制台没有应用错误。
